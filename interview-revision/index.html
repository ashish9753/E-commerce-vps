03

What happens in an API request?

Use this to explain any endpoint.

  1. 1
    React calls the API

    For example, the cart page sends POST /api/v1/orders with the customer’s order details.

  2. 2
    Express middleware runs first

    Helmet adds security headers; CORS checks the frontend origin; rate limiting blocks repeated abuse; JSON parsing reads the request body; auth reads the JWT.

  3. 3
    Route and controller handle the work

    The route chooses the controller. The controller validates input, checks user role/ownership, talks to the database or queue, and returns a consistent response.

  4. 4
    Errors are handled centrally

    Unknown routes go to notFound; thrown errors go to one error handler. This keeps error responses predictable and avoids repeating error code.

Good interview phrase

“Middleware is like a security and preparation layer before the controller runs. It lets me keep cross-cutting work—such as authentication, validation, rate limiting, and error handling—out of every controller.”

04

JWT, login & security

JWT means JSON Web Token.

HeaderPayloadSignature

A JWT is signed, not encrypted. Do not put a password or private data inside it.

Login→Verify password
bcrypt hash→Sign JWT→Browser sends token

How your project uses it

After login, the backend signs a short-lived access token and a refresh token using secret environment variables. On protected requests, auth middleware verifies the access token and places the user data on req.user. Role/permission middleware then decides whether the user may perform the action.

Access token: short life, used often. Refresh token: longer life, used to get a new access token without logging in again.

bcryptHashes passwords with salt. We compare hashes; we never decrypt passwords.
CORSAllows only trusted browser origins to call the API with credentials.
Helmet + HPPHelmet adds safer HTTP headers. HPP protects against duplicate query parameter pollution.
Rate limitRestricts rapid requests, especially login/coupon endpoints, to slow brute-force and spam attacks.
05

Redis queue: the important part

In this project, Bull is the queue library and Redis is its fast storage engine.

Say this

“I use a queue for order processing because placing an order involves important work: checking stock, creating the order, reducing inventory, logging changes, and handling failures. The API adds a job to the Bull queue, Redis keeps the job, and the queue worker processes one job at a time. The current API waits for that job to finish before returning the confirmed order, which keeps the customer response accurate while still serializing critical stock work.”

1Customer places orderAPI validates cart and creates a job
→
2Redis stores jobBull queue: order-queue
→
3Worker processes itChecks stock + creates order
→
4Result savedMongoDB transaction, then confirmed response

Why Redis?

Redis is an in-memory key-value store, so it is very fast. Bull uses it to hold waiting, active, completed, and failed jobs. Redis is not your main permanent database here; MongoDB is.

What if a job fails?

Bull marks it failed and logs the error. Your order processor also rolls back stock when an order fails. In production, use retries, monitoring, and alerts. In development, SKIP_QUEUE=true can process synchronously without Redis.

Important: A queue improves reliability but does not magically solve every race condition. Your project uses a MongoDB transaction during queued order processing, so stock and order updates succeed or fail together.

Schema

A Mongoose schema defines shape and rules: required fields, types, defaults, references, and indexes. It prevents invalid data from being saved.

Reference

Fields like user or product store another document’s ObjectId. Mongoose populate() can fetch the related document when needed.

Transaction

For critical order processing, a transaction groups multiple database writes. If one fails, all changes are rolled back, preventing half-finished orders.

Real-time features, payments & files

Know why each integration exists.

Socket.io

Live chat

Unlike normal request-response HTTP, a WebSocket stays open. The server can instantly emit a message, typing signal, or online status to the other user. Socket authentication verifies the JWT when connecting.

Fonepay / Razorpay

Payments

The backend creates and verifies payment data. For Fonepay, a watcher listens for live payment updates, but the server still confirms payment through the payment-status API—never trust a browser-only success message.

Cloudinary

Media uploads

Multer reads uploaded files in Express. The backend streams them to Cloudinary and stores the returned URL/public ID in MongoDB. It can delete replaced assets too.

Docker, Docker Compose & Nginx

These make deployment consistent and production-ready.

Docker in simple words

A Docker image is a packaged blueprint. A container is a running copy of that blueprint. Your Dockerfiles build the frontend and backend images using Node 20 Alpine; the frontend final image uses Nginx Alpine.

Docker Compose in simple words

Compose starts the frontend, API, and Redis together on one private bridge network. It passes environment variables, starts Redis before the API using a health check, persists Redis data in a volume, and restarts services if they stop.

Nginx servesthe built React files quickly, with gzip compression and long cache rules for static assets.
Nginx proxies/api/* requests to the API container, so the browser sees one origin and avoids a separate public API URL.
SPA fallbackUnknown frontend URLs return index.html, then React Router chooses the correct page.
09

Common interview questions

Open a question, understand it, then answer in your own words.

Why did you use Redis and MongoDB together?

They solve different jobs. MongoDB is the source of truth for permanent business data. Redis is extremely fast and is used here by Bull to manage temporary queue state. Redis can also be useful for caching, sessions, or rate limiting, but this project’s main Redis use is the order queue.

Why use a queue for orders instead of processing directly in the API?

Order processing can be slow and critical. A queue smooths traffic spikes, separates the customer request from heavy work, gives a place to retry/monitor failures, and lets us control concurrency. In this project the worker has concurrency 1 to reduce stock conflicts.

What is the difference between authentication and authorization?

Authentication answers “Who are you?”—login and JWT verification. Authorization answers “What are you allowed to do?”—for example, checking that a user is an admin or owns the order before changing it.

Why access token and refresh token?

A short-lived access token limits damage if stolen. The refresh token lasts longer and obtains a new access token, so the user does not need to log in repeatedly. Both must be protected; httpOnly secure cookies are a common safer storage option for refresh tokens.

How do you prevent overselling?

Before confirming an order, validate stock and update it inside a transaction. Queueing serializes the order work in this project, and the transaction rolls back if any operation fails. For larger scale, use atomic conditional updates and carefully chosen concurrency too.

What does Nginx do in your project?

It serves the production React build, compresses and caches static files, sends API requests to Express, supports SPA routing, and forwards important headers/cookies. It is the web server/reverse proxy in front of the application.

How do you secure the API?

I use Helmet, CORS allowlists, rate limiting, password hashing with bcrypt, JWT verification, role/permission checks, request sanitization, HPP protection, upload limits, environment variables for secrets, and centralized error handling. Security is layered, not one feature.

What would you improve next?

I would add queue retries with exponential backoff and a queue dashboard, automated tests, structured logs and monitoring, Redis-backed caching where profiling shows it helps, token rotation/revocation, database indexes based on real queries, and CI/CD checks before deployment.
